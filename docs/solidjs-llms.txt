## Reference

### solid-js

#### Reactivity

- [createEffect](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/create-effect.md): Creates a reactive effect with **separate compute and effect phases**.
- [createMemo](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/create-memo.md): Creates a readonly derived reactive memoized signal.
- [createOptimistic](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/create-optimistic.md): Creates an optimistic signal that can be used to optimistically update a value
and then revert it back to the previous value at the end of an action.
- [createSignal](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/create-signal.md): Creates a simple reactive state with a getter and setter.
- [flush](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/flush.md): Synchronously processes the pending reactive queue, or runs `fn` in a synchronous
flush scope before draining the queue.
- [isPending](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/is-pending.md): Returns whether the reactive reads inside `fn` depend on an in-flight value change that has not been revealed.
- [latest](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/latest.md): Reads the freshest in-flight value available inside `fn`, falling back to the current settled value.
- [untrack](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/reactivity/untrack.md): Runs `fn` outside of any reactive tracking — reads inside `fn` will not
subscribe the current scope. Returns whatever `fn` returns.

#### Stores

- [createOptimisticStore](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/create-optimistic-store.md): The store equivalent of `createOptimistic`. Writes during an `action` are tentative — they show up immediately but auto-revert (or
reconcile to the action's resolved value) once the action settles.
- [createProjection](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/create-projection.md): Creates a derived (projected) store. Like `createMemo` but for stores: the
derive function receives a mutable draft and either mutates it in place
(canonical) or returns a new value. Either way the result is reconciled
against the previous draft by `options.key` (default `"id"`), so surviving
items keep their proxy identity — only added/removed items are
created/disposed.
- [createStore](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/create-store.md): Creates a deeply-reactive store backed by a Proxy. Reads track each property
accessed; only the parts that change trigger updates.
- [merge](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/merge.md): Merges multiple props-like objects into a single proxy that *preserves
reactivity*. Reads are forwarded to the right-most source that defines the
property, so later sources override earlier ones (like `Object.assign`).
- [omit](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/omit.md): Returns a reactive proxy of `props` with the listed keys hidden. Tracking
on the remaining keys is preserved.
- [reconcile](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/stores/reconcile.md): Returns a draft-mutating function that smart-merges `value` into a store,
preserving fine-grained reactivity: only changed leaves trigger updates.

#### Lifecycle Actions

- [action](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/lifecycle-actions/action.md): The primitive for mutations: imperative async workflows whose *writes span
an async gap* — optimistic write, server round-trip, reconciling write —
where intermediate state must not leak and failure must revert cleanly
(pair with `createOptimistic` / `createOptimisticStore`).
- [affects](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/lifecycle-actions/affects.md): Marks a reactive source or store location as pending while work that will change it is in flight. Marked values remain readable, and derived readers report the pending state until the surrounding action or update settles.
- [onSettled](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/lifecycle-actions/on-settled.md): Schedules `callback` to run **once** after the reactive graph has fully
settled — i.e. Once every pending async read inside the current owner has
resolved and the queue has flushed. Each call registers a single fire; it
does not create an ongoing subscription.
- [refresh](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/lifecycle-actions/refresh.md): Invalidates one reactive source, forcing it to re-execute even if its inputs
haven't changed.

#### Components Context

- [children](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-context/children.md): Resolves a `children` accessor and exposes the result as an accessor with
a `.toArray()` helper. Use this when a component needs to inspect or
iterate over its children rather than just render them through.
- [createContext](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-context/create-context.md): Creates a Context for sharing state with descendants of a Provider in the
component tree.
- [createUniqueId](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-context/create-unique-id.md): Returns a stable id string that matches between server-rendered and
client-hydrated trees. Use it for `<label for>`, `aria-labelledby`, and
other attributes that need consistent ids across SSR.
- [lazy](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-context/lazy.md): Defines a code-split component. The returned component triggers its dynamic
import on first render and suspends through any enclosing `<Loading>`
boundary while the chunk is in flight. Call `.preload()` to start the
import early (e.g. On hover).
- [useContext](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-context/use-context.md): Reads the current value of a context.

#### Components Jsx

- [Errored](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/errored.md): Catches uncaught errors inside its subtree and renders fallback content
instead. The `fallback` prop can be a JSX element, or a callback that
receives the error and a `reset()` function for retry affordances.
- [For](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/for.md): Creates a list of elements from a list.
- [Loading](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/loading.md): Renders a `fallback` while pending async reads inside the subtree settle.
- [Repeat](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/repeat.md): Creates a list of elements from a count.
- [Reveal](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/reveal.md): Coordinates the reveal timing of sibling `<Loading>` boundaries.
- [Show](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/show.md): Conditionally renders its children when `when` is truthy, otherwise renders
the optional `fallback`.
- [Match / Switch](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/components-jsx/switch-and-match.md): A branch inside a `<Switch>`. The first `<Match>` whose `when` is truthy
wins; remaining matches are skipped.

#### Advanced

##### Owner Introspection

- [createRoot](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/owner-introspection/create-root.md): Creates a detached reactive root. The callback receives a `dispose()`
function which, when called, tears down every signal, memo, effect, and
`onCleanup` registered inside the root.
- [getObserver](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/owner-introspection/get-observer.md): Returns the currently-tracking observer (the computation that subscribes to
reactive reads at this point), or `null` if reads here would be untracked.
Used by reactive primitives that need to know whether they're inside a
tracking scope. App code rarely needs this — see `getOwner()` for the
lifecycle owner instead.
- [getOwner](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/owner-introspection/get-owner.md): Returns the current reactive **owner** — the lifecycle node that the next
`cleanup()` / `onCleanup()` / `createSignal()` etc. Will be attached to.
- [isDisposed](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/owner-introspection/is-disposed.md): Returns `true` when an owner has been disposed. Use it to ignore late work after the owner’s component or reactive scope has been removed.
- [runWithOwner](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/owner-introspection/run-with-owner.md): Executes `fn` with the given `owner` set as the current owner. Any reactive
primitives (`createSignal`, `createMemo`, `createEffect`, `onCleanup`,
`cleanup`, etc.) created inside `fn` are attached to that owner, so they
are disposed when the owner is disposed.

##### Specialized Reactivity

- [createReaction](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/specialized-reactivity/create-reaction.md): Creates a reactive computation that runs after the render phase with flexible tracking.
- [createRenderEffect](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/specialized-reactivity/create-render-effect.md): Creates a reactive computation that runs during the render phase as DOM elements
are created and updated but not necessarily connected.
- [createTrackedEffect](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/specialized-reactivity/create-tracked-effect.md): Creates a tracked reactive effect where dependency tracking and side effects happen
in the same scope.
- [onCleanup](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/specialized-reactivity/on-cleanup.md): Low-level reactive-cleanup primitive. Registers a callback that runs when
the surrounding owner is disposed.

##### Store Advanced

- [deep](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/store-advanced/deep.md): Returns a plain (non-proxy) deep copy **and** subscribes the current
tracking scope to every nested change in the source store. Any write
anywhere in the subtree invalidates the consumer.
- [isWrappable](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/store-advanced/is-wrappable.md): isWrappable API reference.
- [snapshot](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/store-advanced/snapshot.md): Returns a plain (non-proxy, non-reactive) deep copy of a store value.
Reading via `snapshot` does **not** subscribe to changes — use this when you
need to hand a stable plain object to non-reactive code (logging,
serialization, structured-clone, network payloads, etc.).
- [storePath](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/store-advanced/store-path.md): Creates a path-based store update for compatibility with Solid 1.x setter calls. Prefer draft-mutating store setters in new Solid 2 code.

##### Jsx Component Primitives

- [createErrorBoundary](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/jsx-component-primitives/create-error-boundary.md): Lower-level primitive that backs the `<Errored>` flow control. Catches
thrown errors inside `fn` and invokes `fallback(error, reset)` instead.
`error` is an accessor for the latest captured error; `reset()` recomputes
the failing sources so the boundary can attempt to recover.
- [createLoadingBoundary](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/jsx-component-primitives/create-loading-boundary.md): Lower-level primitive that backs the `<Loading>` flow control. Catches
pending async reads inside `fn` and renders `fallback` until they settle.
- [createRevealOrder](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/jsx-component-primitives/create-reveal-order.md): Coordinate the reveal timing of sibling loading boundaries.
- [mapArray](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/jsx-component-primitives/map-array.md): Reactively maps an array, reusing the previously-mapped value for unchanged
items.
- [repeat](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/jsx-component-primitives/repeat.md): Reactively renders a callback `count` times, reusing previously-rendered
entries when only the count changes. Underlying helper for `<Repeat>`.

##### Manual Hydration

- [Hydration](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/manual-hydration/hydration.md): Re-enables hydration within a `<NoHydration>` zone (passthrough on the
client). Use it to opt a subtree back into hydration when the surrounding
region was opted out.
- [NoHydration](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/manual-hydration/no-hydration.md): Disables hydration for its children on the client.
During hydration, skips the subtree entirely (returns undefined so DOM is left untouched).
After hydration, renders children fresh.

##### Interop Async

- [enableExternalSource](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/interop-async/enable-external-source.md): enableExternalSource API reference.
- [flatten](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/interop-async/flatten.md): Resolves a children value to its renderable form: unwraps zero-arg functions
(accessors), recursively flattens arrays, and optionally skips
non-rendering values (`null`, `undefined`, `true`, `false`, `""`).
- [NotReadyError](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/interop-async/not-ready-error.md): Represents a read from an async reactive source before its first value is ready. Application code should normally let `Loading` and `Errored` boundaries handle this control flow.
- [resolve](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-js/advanced/interop-async/resolve.md): Awaits a reactive expression and returns its first fully-settled value as a
`Promise`. Pending async reads (`createMemo` returning a promise, etc.) are
waited on; once the expression returns synchronously without `NotReadyError`
the promise resolves with that value. If the expression settles with an
error instead — including an async source that rejects — the promise
rejects with it.

### @solidjs/web

#### Rendering Ssr

- [clientOnly](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/client-only.md): Creates a component that renders only in the browser. The server renders the fallback, and the client keeps that fallback through hydration before mounting the imported component.
- [httpHeader](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/http-header.md): Declares an HTTP response header (or with `append`, appends to one) for
the lifetime of the current reactive scope during SSR — call it bare in a
component or reactive-scope body. Client build: a no-op — the response
head was sent long ago.
- [httpStatus](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/http-status.md): Declares the HTTP response status (and optional status text) for the
lifetime of the current reactive scope during SSR — call it bare in a
component or reactive-scope body where the status is decided (a 404
route, an error fallback). Client build: a no-op — the response head was
sent long ago.
- [hydrate](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/hydrate.md): Attaches a Solid component tree to server-rendered DOM and returns a function that disposes the hydrated tree.
- [isDev](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/is-dev.md): Build-time constant that is `true` in development output and `false` in production output.
- [isServer](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/is-server.md): Build-time constant that is `true` in server output and `false` in browser output.
- [renderToStream](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/render-to-stream.md): Streams an HTML response, flushing the synchronous shell first and then
progressively emitting async-resolved fragments as their `<Loading>`
boundaries settle. Good for time-to-first-byte sensitive pages.
- [renderToString](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/render-to-string.md): Renders a component tree synchronously to an HTML string. Async reads inside
`<Loading>` boundaries emit their `fallback` content; for full-graph
resolution await `renderToStream` instead.
- [render](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/rendering-ssr/render.md): Renders a component tree into a DOM element. Returns a dispose function
that tears the tree down and cleans up reactive scopes when called.

#### Head

- [useHead](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/head/use-head.md): Registers one or more head tag descriptors with Solid's ambient head registry.
- [HeadTag](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/head/head-tag.md): Describes a tag registered with Solid's ambient head registry.

#### Components

- [Dynamic](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/components/dynamic-component.md): Renders an arbitrary custom or native component and forwards the other
props. JSX form of `dynamic()` — same primitive, picked at the JSX site.
- [dynamic](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/components/dynamic.md): Creates a stable component whose rendered component comes from a reactive source. The source can return a component, an intrinsic element name, a promise, or no component.
- [Portal](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/components/portal.md): Renders its children into a different part of the DOM (modal roots,
tooltips, layers that need to escape an `overflow: hidden` ancestor).

#### JSX properties

- [ref](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/jsx-properties/ref.md): Receives a DOM element or composes several callbacks that apply behavior to it.
- [class](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/jsx-properties/class.md): Sets static and conditional class names from strings, objects, or nested arrays.
- [style](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/jsx-properties/style.md): Sets an element's inline styles from a CSS string or an object of declarations.
- [textContent](https://v2-rebuild--solid-docs-v2.netlify.app/reference/solid-web/jsx-properties/text-content.md): Writes plain text as an element's complete contents through an optimized text-only path.
